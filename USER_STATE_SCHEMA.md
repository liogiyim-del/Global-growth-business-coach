# USER_STATE_SCHEMA V1

## Principle

Keep learning knowledge separate from user learning state.

The state should help adapt teaching, not create a permanent judgment profile.

## Mastery Scale

0 Unknown  
1 Recognize  
2 Understand  
3 Apply with Help  
4 Apply Independently  
5 Transfer

## Weakness Confidence

- Signal: 1 observation
- Emerging Pattern: 2 meaningful observations
- Confirmed Weakness: 3+ meaningful observations across cases

A concept not yet taught cannot become a weakness.

## State Sections

### profile
Stable learning preferences and program settings.

### progress
Current day, phase, completed lessons, completed transfer tests.

### mastery
Per skill/concept mastery level and evidence.

### weaknesses
Repeated patterns only.

### learning_log
Lesson and review history.

### case_history
Case topic, result, errors, transfer performance.

### review_queue
What should be reviewed, when, and why.

### prompt_dependency
How much support was required:
0 = independent
1 = small prompt
2 = structured hints
3 = heavy scaffolding

## Error Types

Examples:
- SOLUTION_JUMP
- WRONG_METRIC_LOGIC
- NO_SEGMENTATION
- NO_COHORT
- EVIDENCE_FREE_ASSERTION
- FRAMEWORK_NAME_DROPPING
- NO_PRIORITY
- NO_VALIDATION

## Weakness Aging

A confirmed weakness should weaken in confidence after several successful transfer cases.

Do not keep historical mistakes as permanent identity labels.
