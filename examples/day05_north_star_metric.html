North Star Metric（北极星指标）

从核心用户价值出发设计指标，而不是把 DAU、Revenue 或注册数直接当作“最重要指标”。同时掌握 Input Metric、Proxy Metric、Guardrail Metric 与指标作弊风险。

00 · Learning Goal

本节目标

理解 North Star Metric

知道 NSM（北极星指标）为什么不是“公司最重要的数字”这么简单。

区分指标层级

区分 Outcome Metric（结果指标）、Input Metric（输入指标）、Proxy Metric（代理指标）和 Guardrail Metric（护栏指标）。

会设计 NSM

从用户核心价值出发，而不是从 DAU、Revenue 等现成指标里随便挑一个。

避免指标作弊

理解 Metric Gaming（指标作弊）导致“数字变好但用户价值变差”的风险。

01 · Metric Architecture

指标架构

Business Mission ↓ Core User Value（核心用户价值） ↓ North Star Metric / North-Star-style Metric ↓ Input Metrics（输入指标） ├── Acquisition ├── Activation ├── Retention └── Product Usage ↓ Business Outcome（商业结果） ├── Revenue ├── LTV └── Profit + Guardrail Metrics（护栏指标） → 防止为了主指标伤害质量、体验或长期价值
定义
North Star Metric（北极星指标）是一个能持续反映“核心用户价值被创造”的关键指标，并能帮助多个团队围绕同一方向做决策。
02 · Key Terms

核心术语

术语中文业务含义
North Star Metric北极星指标代表核心用户价值持续发生的主指标。
Input Metric输入指标团队可以通过具体动作影响，并进一步推动主指标的前置指标。
Outcome Metric结果指标较后端的最终结果，例如 Revenue、Profit、Retention。
Leading Indicator领先指标较早发生、能帮助预测后续结果的指标。
Lagging Indicator滞后指标结果发生后才体现，例如季度收入。
Proxy Metric代理指标真实目标难直接测量时，用可观测指标近似代表。
Guardrail Metric护栏指标防止主指标提升却损害其他重要结果。
Metric Gaming指标作弊 / 钻指标把数字做高，却没有创造更多真实价值。
03 · Selection Criteria

一个好的北极星指标需要满足什么

标准判断问题错误例子

04 · Formulas & Examples

指标设计与计算

DAU / MAU（活跃粘性比）

DAU ÷ MAU
DAU 200,000，MAU 800,000 → 25%。
可以反映使用频率，但未必直接等于核心价值。

Successful Value Events（成功价值事件数）

Users × Avg Successful Core Actions per User
40,000 用户 × 平均 3 次成功生成 → 120,000 次。
前提是“成功生成”真的代表可用价值。

Value-Qualified Users（达成价值门槛用户）

VQU = Users Meeting Value Threshold
50,000 周活中 18,000 人至少完成 2 次成功创作并导出 → VQU=18,000。
门槛要通过研究和 Retention 关系验证。

Duolingo TSLW（高质量学习时间）

TSLW ≈ Path Minutes + 0.5 × Other Learning Minutes
路径学习 12 分钟 + 其他练习 6 分钟 → 15 分钟。
这是 Duolingo 官方公开的粗略公式，用于体现不同学习活动的价值权重。
05 · NSM Design SOP

北极星指标设计 SOP

Step 1 — Define Core Value（定义核心价值）

用户为什么使用产品？真正得到的结果是什么？

Step 2 — Find Value Event（寻找价值行为）

哪个行为最接近“价值真正发生”？

Step 3 — Decide Unit & Frequency（决定单位与频率）

按用户数、次数、分钟、订单还是其他单位？按日、周还是月？

Step 4 — Test Long-term Relationship（验证长期关系）

该指标是否和 Retention、LTV、学习效果等长期结果有关？

Step 5 — Build Input Metrics（建立输入指标）

NSM 为什么变化？拆成 Activation、Frequency、Content Supply 等可操作 Driver。

Step 6 — Add Guardrails（加入护栏指标）

防止提高主指标时伤害质量、Churn、退款、成本等。

Step 7 — Test Gaming Risk（检查作弊风险）

团队或用户有没有办法把数字做高，却没创造更多价值？

07 · Deep Case

Duolingo TSLW：核心指标如何从“次数”进化到“高质量价值时间”

案例说明

Duolingo 并未在公开材料中把 TSLW 明确称为整个公司的 North Star Metric。本课程把它作为一个 North-Star-style Metric Design（北极星式指标设计）案例，因为官方称其为最重要的质量指标之一，并用它平衡 Learning Quality（学习质量）与 Growth。

阶段 1：Total Sessions

官方介绍，团队最初关注 Total Sessions，但不同难度课程 Session 长度差异很大。同样 15 分钟，完成 5 个简单 Session 不一定比 3 个困难 Session 更有价值。

问题

Session 数容易把“做得多”误认为“学得好”，是典型 Proxy Failure（代理指标失真）。

阶段 2：Time Spent Learning

团队转向学习时长，但总时长容易被少数超重度用户拉高，仍不能很好代表更广泛学习者。

阶段 3：Time Spent Learning Well

随后形成 TSLW。公开粗略公式为：路径学习分钟 + 0.5 × 其他学习分钟。路径课程被赋予更高权重，因为更直接推动学习者沿课程前进。

如何驱动产品

Duolingo 公开说明 Daily Quests、Monthly Challenges、Leaderboards 等会针对 TSLW 优化，例如将 Monthly Challenge 从 XP 导向改为 Quest 导向，以减少月底集中“刷 XP”。

案例结论
好的核心指标不是“数字最大”，而是尽可能接近真实用户价值，同时还能被团队高频行动。

10 · Key Takeaways

本节结论

1
NSM 首先代表用户价值，不是从 DAU / Revenue 随便选。
2
越容易被刷高的指标，越需要 Guardrail。
3
NSM 下方必须有 Input Metrics，否则团队不知道怎么行动。
4
Proxy Metric 要持续验证，不是一经选定永远不变。
