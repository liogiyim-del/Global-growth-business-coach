01 · Business Case

产品背景

产品：KreaMate AI（虚构教学案例）

业务：AI 图片与短视频生成 App，全球运营。核心用户是社媒创作者、小商家和年轻消费者。

核心路径：看到广告/自然内容 → 安装/访问 → 注册 → 生成第一张图片/视频 → 导出或分享 → 回来继续创作 → 订阅。

韩国市场：团队两个月前增加 TikTok Ads 预算，并启用了一个新的韩语创意方向，主打“10 秒生成韩国流行风格头像”。

业务现象
韩国新注册明显增长，但管理层发现 DAU 和收入没有同步增长。

Leader 要求你在明天下午 Growth Review 前完成第一轮诊断。

2.4 用户研究摘要

Qualitative Evidence

近期 12 位韩国 TikTok 新用户访谈中：

• 8 人说广告让他们以为“韩国流行风头像”是一键固定模板；

03 · Integrated Tasks

综合任务

Task 1 — Growth Health Check（增长健康度）
问题：你认为本月韩国市场是“健康增长”吗？先给一句结论，再给 3 条最关键的证据。
建议结构：结论 → 数据证据 → 为什么这些证据重要。
测试：Growth Map / Business Signal / Metric Relationship
Task 2 — Funnel Calculation（漏斗计算）
用韩国整体数据算出本月：
① Landing → Registration CVR
② Registration → Activation CVR
③ Activation → D7 Retention
④ D7 → Paid CVR
⑤ Landing → Paid Overall CVR

再和上月比较，指出变化最大的一环。用 pp（百分点） 表达。
测试：Day 3 Funnel / Formula / pp
Task 3 — AARRR Diagnosis（AARRR 定位）
① 当前最值得优先关注的 AARRR Stage 是什么？
② 为什么不是只看 Acquisition？
③ 这个 Stage 下面你会建立什么 Sub-funnel（子漏斗）？
测试：Day 4 AARRR / Stage → Sub-funnel
Task 4 — Ownership（主责与协作）
对当前 P0 问题，你会指定谁作为 DRI（直接负责人）？可从 Growth / Growth Marketing / Product / PMM / Korea Local Team / User Ops 中选择。

回答：主责是谁 + 需要谁协作 + 为什么。
测试：Day 2 Ownership / Lever / Cross-functional
Task 5 — Hypothesis & Evidence（假设与证据）
基于现有数据，提出 3 个 Hypothesis（假设）。每个假设都要写：
Hypothesis → Supporting Evidence → 还需要什么 Evidence 才能进一步确认。
测试：Basic Diagnosis / Evidence Thinking
Task 6 — Metric Tree（指标树）
以 Korea Monthly Revenue 为 Parent Metric，至少向下拆 2 层指标树。

要求至少包含：Paying Users、Active / Retained Users、Payer CVR、ARPPU，并指出现有数据最像哪一个分支出了问题。
测试：Day 6 Metric Tree / Identity / Driver
Task 7 — North Star Metric（北极星指标）
如果你要为 KreaMate AI 设计一个韩国市场的 North-Star-style Metric 候选：
① 你选什么？
② 它代表什么核心用户价值？
③ 给 3 个 Input Metrics；
④ 给 2 个 Guardrail Metrics。
测试：Day 5 NSM / Input / Guardrail
Task 8 — Growth Loop（增长循环）
假设产品未来希望利用“用户生成作品分享”形成增长循环。请画出一个简化 Content / Referral Loop：
Value Action → Output → Distribution → New User → Activation → Repeat

并说明当前为什么还不应该把“分享奖励”作为第一优先级。
测试：Day 7 Loop / Funnel vs Loop / Prerequisite
Task 9 — P0 Decision（最终优先级）
如果你只有 2 周，只能推动一个 P0 Growth 项目，你会选什么？

用下面格式回答：
Problem → Mechanism → Evidence → Proposed Direction → Primary Metric → Guardrail → Why P0
测试：Week 1 Transfer / Priority / Business Expression

正式评分仍使用 Foundation Evaluation Rubric V2，但 Weekly Transfer 会额外观察“跨知识迁移”。

通过标准
不是“全部算对 = 通过”。

真正通过意味着：面对综合 Case，你已经开始形成稳定路径——先看业务结果，再拆指标、定位阶段、确认 Owner、提出假设和 Evidence，最后才给 P0。
