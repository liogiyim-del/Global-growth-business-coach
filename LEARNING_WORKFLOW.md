# LEARNING_WORKFLOW V2

## Objective

Move the learner through four layers:

1. Knowledge
2. Understanding
3. Know-how
4. Business Thinking

## Core Learning Path

Knowledge Map
→ Vocabulary
→ Concept / Model
→ Concept Relationships
→ Business Triggers
→ Diagnosis Know-how
→ Execution Playbook
→ Metrics
→ Deep Case
→ Practice
→ Transfer

## Lesson Modules

### 0. Knowledge Map Position
Where this topic sits, upstream/downstream, confusing neighbors, later dependencies.

### 1. Industry Vocabulary
Term → Chinese meaning → business usage → confusing concept → example.

### 2. Core Concept / Model
What → Why → Where → When to use → When not to use → What comes next.

### 3. Concept Relationships
Connect the topic to adjacent growth metrics and mechanisms.

### 4. Business Signals
Show what real signals should trigger this knowledge.

### 5. Diagnosis Know-how
First check → second check → segmentation → branches → next evidence.

### 6. Execution Playbook
Problem → Mechanism → Tactic.

### 7. Tactic Schema
- Tactic
- Solves
- Mechanism
- Suitable When
- Not Suitable When
- Execution Know-how
- Metric
- Risk
- Example

### 8. Metrics & Data
Metric → formula → example → business meaning → pairing → misread.

### 9. Deep Case
Context → Problem → Signal → Diagnosis → Hypothesis → Evidence → Mechanism → Execution → Metrics → Result → Trade-off → Why → Failure → Transfer.

### 10. Overseas Lens
Only when material:
Market / Culture / User Behavior / Channel / Product Expectation / Pricing / Localization / Regulation.

### 11. Interview Lens
What an interviewer is testing, strong structure, common black words.

### 12. Quick Check
Basic comprehension before the business case.

### 13. Daily Challenge
Only use knowledge and know-how already taught.

**Hard Stop after Challenge.**

## Teaching Ratio

- Day 1–15: Knowledge/Know-how 70%, Case/Practice 30%
- Day 16–30: 55% / 45%
- Day 31–45: 40% / 60%
- Day 46–55: 25% / 75%
- Day 56–60: 10% / 90%

## Lesson Generation Logic

For each curriculum day:

1. Read topic spec.
2. Read relevant mastery and weakness state.
3. Select required modules.
4. If metric is calculable, add formula section.
5. If a common business failure exists, add diagnosis and cause table.
6. If execution exists, map tactics to mechanisms.
7. If a real case materially improves learning, research and source it.
8. Build interview transfer.
9. Add quick check.
10. Add challenge and stop.

## Post-Challenge

After user submits:

1. Evaluate with stage rubric.
2. Separate:
   - correct
   - incomplete
   - misconception
   - not-yet-taught
3. Explain improved reasoning path.
4. Record observations.
5. Update mastery.
6. Add review item if needed.
7. Never mark weakness from one observation.
